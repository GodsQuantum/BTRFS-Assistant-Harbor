## Where QA outputs live

Git contains code, tests, reports and reproducible runners. VM disks, source backup archives, raw logs, screenshots, release candidates, manifests, and build intermediates stay **outside Git** under the canonical workspace `notes/cert-alpha9-20261015/` and `build/`. Keep ReaR ISO, restored raw, package binaries, test logs and failure reproductions for audit.

## Maintenance / workflow invariants

1. Read the canonical workspace `README.md`, `HANDOFF_CURRENT.md`, matrix and Git HEAD; work only on Cloud9/DEV700 NVMe. Check whether concurrent sessions changed the branch before modifying anything.
2. Preserve original alpha9 GitHub release/tag and any official Btrfs Assistant installation. Never alter Cloud9 mounts, ACL, SyncBridge, NAS storage or production snapshots/backups.
3. Consult current official upstream docs. For each change: record the triggering failure, make a focused patch and add a regression test; preserve failure logs.
4. Always test **the exact commit being packaged**. Rebuild the DEB/RPM/Arch package after source changes, and repeat lifecycle tests in the distro VM. Never pass a previous package test off as a new one.
5. Verify and retain package SHA-256, toolchain versions, commands, exit codes and runtime logs. Keep unsupported risky paths refused by default.
6. Release only after a matrix review that distinguishes PASS(scope), PARTIAL, UNSUPPORTED and NOT_TESTED. A working VM does not prove physical machines or all desktop environments.
7. Clean only named disposable QEMU overlays, QA Docker containers, generated target/build trees and temporary jobs once artifacts/logs and parent dependencies have been audited. Leave historical proof and all other CT/LXC services unchanged.

## Safety boundaries

ReaR supported proof currently covers **one Btrfs root + VFAT ESP, x86-64 UEFI, GRUB, Secure Boot OFF** in disposable Debian 13 QEMU. No LUKS/LVM/RAID, multi-root or systemd-boot claims. CAS destructive pruning on SMB/NFS is forbidden. Keep fail-closed on corruption, wrong repo UUID and stale deletion plans.
